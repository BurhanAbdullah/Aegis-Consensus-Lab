## Architecture at a glance

The canonical model represents each validator using:

- **Trust vector** (T_{i,k}\in[0,1]^m), with aggregate trust (\tau_{i,k}=w^TT_{i,k}).
- **Detector evidence** (E_{i,k}\in[0,1]), derived from normalized observable detector channels.
- **Temporal drift** (D_{i,k}\in[0,1]), computed from changes between consecutive detector observations; it is not a ground-truth attack label.
- **Predictive risk** (R_{i,k}\in[0,1]), updated from risk history, evidence, and drift.
- **Governance influence** (G_{i,k}), used to determine active validators and total governance weight.
- **Adaptive quorum** (q_k) and threshold (Q_k=q_kW_k).
- **Authenticated prepare/commit certificates**, bound to a common height, view, phase, and proposal hash. A validator contributes at most once per context.

The reference implementation makes certificate construction the source of finalization. This is a deterministic consensus/governance model driven by scenario inputs—not a demonstrated deployment in a physical grid.

## Mathematical scope and assumptions

For fixed exogenous detector evidence and drift, the interior state Jacobian is

\[
J_i=\operatorname{diag}\big((1-\rho_i-\ell_iE_i)I_m,\ a_i\big).
\]

Its spectral radius is \(\max(|1-\rho_i-\ell_iE_i|,|a_i|)\). The local stability result is conditional on an interior differentiable state and fixed exogenous inputs. If detector evidence or drift is generated by endogenous state variables, those states and derivatives must be included in an augmented Jacobian.

The weighted-quorum safety claim is also conditional: it relies on authenticated certificate context, honest validators not equivocating, and the stated Byzantine governance-weight bound. Read the assumptions alongside the [model specification](research/transactions_rebuild/FINAL_MODEL_SPEC_v2.md) and the [proof obligations](research/transactions_rebuild/PROOF_OBLIGATIONS.md).

## Run the Transactions tests

The tag4 validation workflow uses Python 3.12 and runs:

```bash
python -m pip install --upgrade pip pytest numpy
PYTHONPATH="$PWD/research:$PWD/research/transactions_rebuild:$PWD/research/transactions_rebuild/kernel" \
  python -m pytest -q research/transactions_rebuild
```

The recorded GitHub Actions run on commit `f5a13a0570a1bdb3bfaa9a1102b0951b7fe76d4e` reported **77 passed in 0.47s**. See the [workflow run](https://github.com/BurhanAbdullah/Aegis-Consensus-Lab/actions/runs/38173887211). This is a recorded CI result for that exact commit, not a claim that every branch or later commit has been tested.

The stricter Transactions workflow additionally runs independent mathematical cross-validation, repeats it to check deterministic output, generates comparison tables from frozen traces, and verifies release-data provenance. See [the strict workflow definition](.github/workflows/tag4-transactions-strict.yml).

## What the results support

- **Implementation correctness within tested cases:** the recorded suite passes for the tested commit.
- **Mathematical consistency:** the release manifest reports 1,000 cross-validation cases, maximum equilibrium residual of approximately \(1.11\times10^{-16}\), maximum finite-difference Jacobian relative error of approximately \(9.65\times10^{-11}\), zero stability-classification mismatches, and byte-identical repeated cross-validation output.
- **Historical experiment reproducibility:** the archived traces and phase-space CSVs are versioned; generated publication comparison artifacts are derived from the frozen traces.
- **Predictive benefit:** the archived phase-space comparison does **not** establish a statistically significant global predictive advantage. Do not describe superiority as proven.
- **Physical-grid validation:** the previously stated 9,450-case physical-grid claim is excluded from the release because the required raw case-level and controller evidence is incomplete. It is **not independently verified** by this repository.
- **Manuscript readiness:** the repository does not certify compilation or final submission readiness. Build the exact manuscript and inspect all generated tables and figures before submission.

## Reproducibility checklist for readers

- [ ] Record the exact branch, tag, and commit SHA used.
- [ ] Run the test command above and save the complete output.
- [ ] Run the strict cross-validation and provenance checks from the workflow.
- [ ] Regenerate comparison tables; do not hand-edit generated artifacts.
- [ ] Confirm every table and figure traces to a committed source dataset or script.
- [ ] Keep theoretical results separate from empirical results and physical-system claims.
- [ ] Compile the exact manuscript source and inspect the PDF before submission.

## Claim boundary

A passing test suite establishes that the tested assertions passed under the tested environment. It does not, by itself, prove Byzantine safety under every adversary, general stochastic convergence, predictive superiority, real-time deployment readiness, or physical-grid mitigation. Those require separate proofs, assumptions, raw evidence, and validation.
